# Translations (i18n)

The site speaks seven languages: `en`, `pt`, `es`, `fr`, `de`, `zh`, `ja` (`SUPPORTED_LANGS` in `src/i18n.js`, texts in
`src/locales/<lang>.json`, one flat key → text object per language). Every streamer page and the public tip page
(`/tip/:username`, which viewers see) is translated. English is the source: a key is written in `en.json` first.

## How a visitor gets a language

1. The `lang` cookie, set by the language switcher (`POST /set-language`, one year).
2. Otherwise English. The browser's own language (`Accept-Language`) is not used, so no page varies by it
   (`fromAcceptLanguage()` in `src/i18n.js` is kept, unused, should the site ever follow the browser again).

`res.locals.t(key, params)` is `t(lang, key, params)` in every view. A key missing from a language falls back to the
English text, then to the key itself; a `{{name}}` the call does not fill prints as nothing.

## The rule

- Every text a person reads goes through `t('key')`: text nodes, `placeholder`/`title`/`alt`/`aria-label`, `confirm()`
  and `alert()` texts, and the answers of routes (`res.status(400).json({ error: res.locals.t('...') })`). No English
  typed into a view.
- **Every key in `en.json` must exist in all seven locale files.** `tests/i18n.test.js` enforces it (and that each
  translation keeps its English text's `{{placeholders}}`, that no text is empty, and that every key the source names
  is in `en.json`), so add the six translations in the same change as the English text.
- Error codes, not texts, travel in URLs: a redirect carries `?error=<code>`, and the page maps a code it knows to a
  `t()` key (`errorMessage()` in `src/services/donationSettings.js`). Never print text from the URL.
- Numbers, money and dates use `Intl` with the page language (`Intl.NumberFormat`, `Intl.DateTimeFormat`,
  `Intl.DisplayNames` for currency names), not keys.
- Placeholders are `{{name}}`. A count that needs a plural has two keys, `key` (1) and `key_plural`, and the view picks
  one.

## Markup inside a sentence

A sentence with a link, a bold word or code must never be printed with `<%- t(...) %>`: a translation would then be able
to add markup. Print it through `rich(key, { field: html })` (with `esc()`; both come from `res.locals` next to `t()`,
set in `src/server.js`, and no view defines its own): it escapes the whole translation and turns
only the `{{fields}}` the page names into HTML. Fields come in pairs around the words, for example
`{{a}}link text{{aEnd}}`, `{{b}}…{{bEnd}}` for bold and `{{c}}…{{cEnd}}` for code, so the translated sentence decides
where the markup goes. (The tip, dashboard, donation, giveaway, reward and sponsor-message pages use another equivalent:
the view asks for the sentence with a marker in place of the link and splits on it. Both keep the output escaped; use
`rich()` for new pages.)

## Texts a script needs

A page's inline script gets its texts from the server, as one JSON object printed into the page:
`const I18N = <%- JSON.stringify({ saved: t('...'), ... }).replace(/</g, '\\u003c') %>;`. A text with a `{{field}}` is
filled by a one-line helper in the script, and the script writes it with `textContent` (or through an escape), never
`innerHTML`.

## Tests

- `tests/streamerViewsI18n.test.js` (the home, account, report, tutorial, landing, donate, login, guild, overlay, builder,
  chatbot, YouTube chatbot, multistream, moderation log, link-result and disabled-account pages) and `tests/i18nViewsPart1.test.js` (the
  tip, dashboard, donation, giveaway, reward and sponsor-message pages) read the view source and render it: no English
  outside `t()`, every key exists in `en.json`, every `{{field}}` is filled, the inline scripts parse, and a translation
  holding markup comes out as text. **A new page is added to the `PAGES` list of one of them**, with sample data for
  its states (`PAGE_LOCALS` in the first, `SAMPLES` in the second), so it is held to the same rules. The first also
  renders every one of its pages in all seven languages (no `{{field}}` left, no `undefined`, every inline script
  parses) and checks the builder's default sponsor name and font sample per language.
- `tests/i18n.test.js` keeps the seven locale files in step with `en.json`: the same keys, the same `{{placeholders}}`
  and `{chat variables}` in every text, no empty text, and every key a view, route or service names exists. A key built
  at run time (`t('lang.' + code)`) goes into `DYNAMIC_KEY_FAMILIES` there, with every value it can take. A failure
  names the language and the key.
- `src/i18n.test.js` covers `fromAcceptLanguage()` (not used by the site today); `src/server.app.test.js` checks that pages are English unless the `lang` cookie says otherwise.

## What is not translated

- The Racing product and the Atleta Racing app (`racing-*`, `tracks`, `iracing*` views, `bridge/`), the admin dashboard,
  the legacy `pricing`/`subscription` pages (nothing links to them), `vtuber`, and `custom-overlays` (disabled).
- The lines the bots post in Twitch and YouTube chat: the bot has no per-streamer chat language, so they stay English.
- Data: sponsor names, the alert texts a streamer types in the builder, channel names.
- The builder's font sample (`overlayBuilder.text.fontSample`, the line shown in each font of the font picker) stays the
  English line in `zh` and `ja` on purpose: the picker's fonts (Outfit, Inter, Poppins, Roboto Mono, Press Start 2P,
  Permanent Marker, Bangers) have Latin letters only, so a Chinese or Japanese sample would show the same system font in
  every row and the picker would stop showing the fonts. The other five languages translate it.

## For translators

Keep every `{{placeholder}}` and each pair of markers (`{{a}}`…`{{aEnd}}`, `{{b}}`…`{{bEnd}}`, `{{c}}`…`{{cEnd}}`) and
put them around the right words. Single braces (`{user}`, `{title}`, `{cost}`, `{username}`) are chat-template
variables that streamers type, not placeholders: keep them as they are. Product and platform names (Atleta, Twitch,
YouTube, OBS, PayPal, StreamElements, Discord, Spotify, VRM), command names (`!song`, `!permit`) and file types
(mp3, wav, ogg) stay as they are. Texts in a language file are plain text: no HTML.
