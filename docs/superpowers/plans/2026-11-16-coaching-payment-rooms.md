## Planning decisions (answers to the brief's open questions)
1. **States.** `waiting` → (accept) `awaiting_payment` → (verified capture) `confirmed`. Unpaid at the deadline → `expired`. A free length goes `waiting` → (accept) `confirmed`. `HOLDING = ['waiting', 'awaiting_payment', 'confirmed']`; `MAX_UPCOMING`, `MAX_REQUESTS_PER_DAY` and the overlap transaction use it. A booking is **paid** when it has a recorded capture (`paid_at` not null).
2. **Lengths and prices.** `coaching.LENGTHS = [30, 60, 120, 180, 240, 300]`. Stored per streamer as JSON on `coaching_settings.lengths`: `{"60": {"on": true, "price": 2500}, ...}` (price in cents, the tip page's currency, `streamers.donation_currency`, EUR when unset). Default for every streamer (and every existing row, read-time default when the column is NULL; no data step): 30 off/0; 60 on/2500; 120 on/4500; 180 on/6000; 240 on/7000; 300 on/8000. At least one length must stay on. Price 0–100000 (0.00–1000.00), whole cents.
3. **Free lengths are allowed:** price 0 = no payment; accept confirms it at once (and makes the room, decision 9). The page shows "Free".
4. **Non-EUR currency:** the defaults keep the same numbers in the streamer's own currency; until the streamer has saved prices once (`coaching_settings.prices_saved_at` NULL) and their currency is not EUR, the coaching page and the card show "Check your prices: they are in <currency>". Each booking stores its own `price_cents` and `currency` at request time, so a later price or currency change never changes a booking.
5. **No PayPal email:** a paid length needs `streamers.paypal_email`. Without it the coaching page and the card say so (link to `/dashboard/donations`), the booking page offers only free lengths, and accept of a paid request is refused (`no_paypal`).
6. **Payment deadline:** `pay_by = min(accepted_at + 2 h, starts_at − 15 min)`. Accept of a paid request is refused (`too_close`, a translated message on card and schedule) when `pay_by` would be less than 10 minutes from now (i.e. the start is under 25 minutes away). The streamer can still decline. Free lengths can be accepted until the start.
7. **Expiry:** a minute tick (decision 12) expires `awaiting_payment` bookings past `pay_by`: before expiring it reads back any open PayPal order of that booking (a capture found → confirm instead). Expired: both sides get a DM (`coaching.message.*`), the time frees up.
8. **Payment** (`services/coachingPayments.js`, patterns from `services/tipCapture.js`): `POST /coaching/:login/bookings/:id/pay` (signed-in viewer who owns the booking, state `awaiting_payment`, before `pay_by`) creates a PayPal order with `payee: { email_address }` = the streamer's PayPal email, the booking's price and currency, `custom_id` = booking id, and a row in a new `coaching_payments` table (order_id PK, booking_id, streamer_id, amount_cents, currency, payee_email, status `created|captured|refused`, capture_id, created_at, captured_at). The return route `GET /coaching/:login/paid?token=<orderId>` captures (`Prefer: return=representation`), reads the order back when the answer is lost or slow, and counts it only if: the order row exists and belongs to this streamer and booking, the payee matches, amount and currency equal the booking's, the capture is COMPLETED. Idempotent: a capture id is recorded once; a replay changes nothing. Recorded on the booking: `paid_at`, `paid_amount_cents`, `paid_currency`, `paypal_order_id`, `paypal_capture_id`. Not in `donations`, no `announceTip`, no tip goal, no TTS, no chat line. A **late capture** (booking already expired): record the payment; if its time is still free, confirm the booking; else keep it expired, set `payment_issue = 'late'`, DM the streamer that a payment arrived for an expired booking and must be refunded in PayPal (shown on the schedule). The PayPal token/order/capture helpers move from `src/routes/tip.js` into `src/services/paypal.js` (same behaviour; tip.js imports them). The pay route needs no CSRF exemption (the viewer's sign-in gives a token; the page sends it). Daily: `coaching_payments` rows `created` older than 24 h are read back once and then dropped.
9. **No cancel after payment:** a paid booking has no Cancel (streamer) or Withdraw (viewer); the routes answer `paid` (409). Before payment, decline/cancel/withdraw work as today. Bookings confirmed before this release (no price, `paid_at` NULL) keep today's Cancel/Withdraw and get no room.
10. **Rooms** (`services/coachingRooms.js`): made when a booking becomes confirmed by payment, or on accept of a free length, only if the streamer set a Coaching category. New table `coaching_rooms` (booking_id PK, streamer_id, guild_id, category_id, role_id, channel_id, state `making|open|closing|closed|failed`, error, close_at, transcript_status, created_at, updated_at). Steps: create role `coaching-<username>-<YYYY-MM-DD>` (Discord username lowercased, `[a-z0-9_.-]` only, date in the streamer's zone, cut to 100 characters) with no permissions, give it to the viewer, create a voice channel of the same name in the category with overwrites: `@everyone` deny View Channel + Connect; the role allow View Channel, Connect, Speak, Send Messages, Attach Files, Read Message History; the coach (streamer's Discord id) the same allows; the bot itself the same plus Manage Channels. Each step's id is written to the row as it is made, so a restart can finish or clean up. `close_at = end of session + 30 min`. The confirmation DM links `<#channelId>`; the booking page and the schedule show the link. A failure keeps the booking confirmed, stores `state='failed'` + an error code (`no_category`, `missing_permissions`, `viewer_not_member`, `discord_down`, `failed`), shown on the schedule and the card with a **Retry room** button (`POST /dashboard/api/coaching/bookings/:id/room`, deletes any half-made pair first). The free-text "Where the session happens" stays as the fallback, shown when a booking has no open room.
11. **Category setting:** `coaching_settings.category_id`, picked on `/dashboard/coaching` from the coaching server's categories (a JSON list the route gives; empty while Discord cannot be reached, then the saved one is kept). Save checks the bot's permissions on the category (Manage Channels, Manage Permissions (Manage Roles overwrite), View Channel, Connect, Speak, Send Messages, Attach Files, Read Message History) and Manage Roles at server level, and refuses with `category_permissions` naming the missing ones (translated permission names). Optional: no category = no rooms, the where text is used.
12. **Minute tick** (`coachingRooms.startTicks()` or a small `services/coachingTick.js`, started in `src/index.js` boot and stopped on shutdown, `.unref()`, one run at a time): expire unpaid bookings (7), read back stale orders (8), finish or clean up `making` rows older than 2 minutes, close rooms past `close_at`. Close: read the voice channel's text chat (REST `messages.fetch`, all pages), build a `.txt` transcript (header: streamer, viewer, session time; lines `YYYY-MM-DD HH:MM <display name>: <text>` in the streamer's zone with the zone named in the header; attachments listed by file name with "(attached)" or "(too big to send)"), DM it to the viewer and the coach with the attachments re-uploaded (each file ≤ 10 MB, at most 10 files and 10 MB per message, extra messages as needed; Discord limits). Then delete the channel and the role, `state='closed'`. A DM failure is recorded in `transcript_status`, never retried endlessly (one try per side). **Message Content intent:** add `GatewayIntentBits.MessageContent` to the client in `src/discord.js`; if Discord refuses the login with "disallowed intents" (close code 4014), `discordLogin.js` logs it loudly once and logs in again without it, and `discord.hasMessageContent()` returns false; then a transcript is not sent and `transcript_status='no_intent'` is shown on the schedule ("Switch on Message Content in the Discord Developer Portal"). Never send an empty transcript; a room with no messages sends a one-line "No messages were written" transcript.
13. **Clean-up when a booking goes away otherwise:** admin Remove of an account and `twitchAccountChanged` do not reach Discord today; before `STREAMER_OWNED_ROWS` deletes the rows, `accountLifecycle` calls `coachingRooms.removeAllFor(streamerId)` (best-effort, never throws, deletes channel + role). Changing the coaching server or category leaves existing rooms until they close (the row keeps its guild/category ids).
14. **Booking page, sign-in first:** signed out → only Connect Discord (with the coach's name and what happens next). Signed in, not a member → the join step (existing). Member (or Discord could not say) → pick length (the streamer's lengths that are on, each with its price or "Free", only those with a free start), day, time, note, Request. My bookings: state, length, price, when, and per state: awaiting payment → **Pay <price>** + "Pay by <time>" (viewer's zone); confirmed → the room link (`https://discord.com/channels/<guild>/<channel>`) or the where text; expired/declined/etc. as today. Return from PayPal lands on the page with `?paid=1` or an error code.
15. **Streamer side:** schedule lines show price, state pills for awaiting payment (with the deadline) and paid (amount), the room link or room error with Retry, transcript status after the session, `payment_issue` late warning. Past list shows paid amounts. No separate payments history or CSV. Card: waiting requests show length and price; the next session shows paid/awaiting payment; the PayPal-missing and check-prices notes; the room error count.
16. **Lengths over 1 h:** `freeStarts` already requires the session to end inside the day's window and steps 30 min; it needs only the new `LENGTHS`. The page lists a length only when it has at least one free start in the 14 days.
17. **DMs (`coachingMessages.js`):** new kinds: accepted-pay (price, pay-by, link to the page), confirmed (room link or where text), expired (both sides), payment-late (streamer), transcript. All through `escapeLinkText`, no mentions, in the booking's language (viewer) or the settings' language (streamer).
