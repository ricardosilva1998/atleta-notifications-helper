# Coaching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A streamer sets weekly coaching hours; a viewer signs in with Discord (never as a streamer), joins the streamer's server, and requests a 30-minute or 1-hour time; the streamer accepts, declines or cancels from the dashboard; Atleta messages both sides on Discord.

**Architecture:** One pure rules module (`services/coaching.js`: hours, free times, states, validation) shared by a booking service (`services/coachingBookings.js`: the actions and their Discord messages) that two routers call: the public booking page (`routes/coaching.js`, `/coaching/:username`) and the streamer's side (`routes/coachingDashboard.js`, inside the dashboard router: `/dashboard/coaching` and its JSON routes). Viewers get their own sign-in (`viewer_sessions`), reusing Discord's already-registered redirect `/auth/login/callback` with a purpose cookie. Direct messages, membership and invite checks are new functions in `src/discord.js`. The Coaching working card sits on the Twitch tab after Giveaways.

**Tech Stack:** Node 24 CommonJS, Express 5, EJS, better-sqlite3, discord.js v14, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-29-coaching-design.md` (mockup `docs/superpowers/specs/assets/2026-10-29-coaching-mockup.html`). Read both before any task.

## Global Constraints

- Plain CommonJS; all SQL in `src/db.js`; no `require()` inside EJS; config via `require('./config')`.
- Every user-facing text through `t()` in all 7 locales (`src/locales/{en,pt,es,fr,de,zh,ja}.json`), added with `node scripts/locale-keys.js add <file.json>` and translated with `node scripts/locale-keys.js set <lang> <file.json>`; `tests/i18n.test.js` must pass. Sentences with a link or bold word go through `rich()`. Error codes, never texts, in URLs.
- A view that includes `header.ejs` ends with `<%- include('footer') %>`; a view without the header includes `csrf.ejs` in `<head>`; JSON printed into a script ends in `.replace(/</g, '\\u003c')`.
- Migrations boot clean twice on a fresh database with no `[DB migration]` line (CI). New tables with `streamer_id` go in `STREAMER_OWNED_ROWS`.
- Every outbound call has a deadline; Discord down, not ready, or `DISCORD_DISABLED=1` never throws out of a route.
- Tests never touch the network, production or `data/` (in-memory SQLite through the `Module._load` stub of `src/db.accounts.test.js`; fakes for `src/discord.js` and `fetch`).
- Spec values: lengths **30 and 60** minutes; starts on **:00 and :30**; a session ends by its window's end; **14 days** (today + 13, in the streamer's zone); bookable until **1 hour** before start; **2** upcoming (waiting or confirmed) per viewer per streamer; note **≤ 300** characters; "Where the session happens" **≤ 150**; one window per weekday; whole days off; invite rechecked **at most once an hour**; viewer sign-in **7 days**; past sessions shown **30 days**; Discord sign-in scope **`identify`** only.
- Looks: the site's tokens (`header.ejs`), the working cards' classes (`views/cards/_style.ejs`, `_tiles.ejs`), compact as in the mockup; nothing that looks like a generic admin or calendar product.
- Before each commit run the whole unit suite: `node --test "src/**/*.test.js" "tests/**/*.test.js" "bridge/test-*.js"`. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Daylight saving.** A week across Europe/Lisbon's change (Sunday 25 October 2026): 18:00 local stays 18:00 local; the UTC instants move by an hour. (Task 1)
2. **A viewer far from the streamer.** Lisbon 18:00–22:00 seen from Asia/Tokyo falls on the next local day (02:00–06:00); the day strip groups by the viewer's day and shows that day. (Task 5)
3. **Two overlapping requests.** A 1-hour request at 19:00 and a 30-minute one at 19:30 for the same streamer: the second answers `taken`; a third viewer's 20:00 still works. (Task 2)
4. **Acting too late or on someone else's booking.** Accept on a waiting booking whose start has passed answers `too_late`; a viewer cancelling another viewer's booking answers `not_found`; a booking id of another streamer answers `not_found`. (Task 4)
5. **Viewer-typed text.** A note `@everyone [win](https://evil.example)` reaches the streamer's Discord message with its link text escaped (`escapeLinkText`) and no mentions (`allowedMentions: { parse: [] }`); on the pages a name or note holding `<script>` prints as text. (Tasks 4 and 5)
